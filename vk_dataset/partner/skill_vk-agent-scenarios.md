## Общие правила

- Рабочая папка — `vk_dataset`. Каждая команда vk_dataset: `..\venv\Scripts\python.exe vkds.py <глагол> ...`. Не вызывай `.bat`. Подробности глаголов — скилл `vk-dataset`.
- Бюджет: перед каждой серией вызовов назови её цену; у задания есть общий бюджет вызовов — не выходи за него без «да» владельца. Скачивание — только после «да» и с `--budget N` (смета плюс 20 %). После серии команд — `budget`, цифры месяца в `STATUS.md`.
- Вопросы владельцу — только инструментом `question` (AGENTS.md §10).
- В контекст — только сводки команд, `report.txt` и короткие подсчёты скриптом. Никогда не читай целиком `_candidates.json`, `_wall.json`, `_manifest.csv`, `verdicts.csv` и папки с фото.
- Листы `sheet.jpg`, `rejected.jpg`, `band.jpg`, `accepted.jpg` смотри по одному.

## Сценарий A: найти группы

1. Составь сетку из 5–8 запросов: синонимы, сокращения, латиница, «старые фото», «история», города и заводы темы. Назови цену: по 1 вызову на запрос и 1 на каждые 500 найденных групп.
2. `..\venv\Scripts\python.exe vkds.py search groups --q "<запрос>" --q "<запрос>" ... --count 20 --out <тема>`.
3. Если поиск ответил, что `groups.search` недоступен с этим ключом: доложи и `question` — «Назовите группы сами» / «Отменить»; дальше с шага 5 по названным группам.
4. Отбери до 10–12 открытых кандидатов (не «закрыт», не «частный») по названию, описанию, участникам и числу запросов, которые их нашли.
5. По каждому: `..\venv\Scripts\python.exe vkds.py sample <группа> --sheet --out <тема>` (1 вызов). Нет фото на первой странице стены — тот же вызов с `--from albums` (2 вызова).
6. Посмотри каждый `<base>\<тема>\_samples\<папка группы>\sheet.jpg` и напиши по строке на группу: что на фото, доля по теме, мусор.
7. `question`: какие группы брать — «Взять отмеченные мной (N)», «Взять все открытые», «Свой список», «Посмотрю листы сам».
8. По каждой выбранной: `scan albums <группа> --out <тема>` и `scan wall <группа> --out <тема>`.
9. Сметы без вызовов: `albums <группа> --min-side 512 --out <тема> --dry-run` и `wall <группа> --min-side 512 --out <тема> --dry-run`.
10. `question`: план и смета (группы, фото, вызовы, остаток месяца) — «Да» / «Нет» / «Покажи подробнее».
11. После «да»: `albums <группа> --min-side 512 --out <тема> --budget N` и `wall <группа> --min-side 512 --out <тема> --budget N`.
12. Контрольный повтор тех же команд, `budget`, `STATUS.md`, отчёт.

## Сценарий B: скачать и отобрать по условию

1. Разведка и скачивание — шаги 8–12 сценария A по названным группам.
2. Дубли по каждой папке группы: `..\venv\Scripts\python.exe ..\deduplicate\dedup.py <папка группы> --gpu --dry-run`, доложи, потом без `--dry-run`.
3. Напиши владельцу команды пробы judge для каждой папки группы, условие — дословно из задания, и жди его «готово»:
   `..\judge\run.bat "<папка группы>" --condition "<условие>" --endpoint http://127.0.0.1:11434/v1/ --dry-run --limit 200`
4. После «готово»: прочитай `<папка группы>_rejected\_judge\report.txt`. Если отказов подозрительно много или «не ясно» почти всё — `question`: «Условие понято верно?» — «Да, дальше» / «Переформулировать условие» / «Показать примеры отказов».
5. Напиши владельцу команду полного прогона и жди «готово»:
   `..\judge\run.bat "<папка группы>" --condition "<условие>" --images --sheets --endpoint http://127.0.0.1:11434/v1/`
6. После «готово»: прочитай `report.txt`; при нужде — подсчёт по причинам одной строкой:
   `..\venv\Scripts\python.exe -c "import csv,collections,sys; r=list(csv.DictReader(open(sys.argv[1],encoding='utf-8-sig'))); print(len(r), collections.Counter(x['final'] for x in r), collections.Counter(x['reason'] for x in r))" "<папка группы>_rejected\_judge\verdicts.csv"`
7. Посмотри по одному `rejected.jpg` и `band.jpg` в `<папка группы>_rejected\_judge\`; напиши, какие отказы верные, какие ошибочные.
8. `question`: итог отбора — «Оставить так» / «Вернуть всё (--undo)» / «Поправить условие и прогнать заново» / «Посмотрю листы сам».
9. «Вернуть всё»: напиши владельцу `..\judge\run.bat "<папка группы>" --undo`. Новое условие — та же команда шага 5 с новым `--condition` и ключом `--rejudge`. Для узкого условия предложи свои подсказки `--positives "..."` и `--negatives "..."` (по-английски, коротко, только видимое на фото).
10. Отчёт: принято, отбраковано, не ясно, размер полосы VLM, сколько фото посмотрела VLM; `STATUS.md`.

## Чего не делать

- Не запускать judge самому, ни пробу, ни прогон, ни `--undo`: у оболочки OpenCode тайм-аут, а модель judge — твоя же модель. Команды judge пишет агент, запускает владелец. `--help` judge читать можно.
- Не качать без разведки, сметы и «да».
- Не повторять команду после ошибки лимита ВК (код выхода 2 с отметкой limit_hit): доложить и ждать сброса.
- Не читать большие файлы в контекст.
- Не править файлы в `vkds\`, `tools\`, `..\judge\` и других папках dataset_tools.
- Не выводить и не читать токен.
