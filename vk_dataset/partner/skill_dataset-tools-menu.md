## Меню в начале сессии

После чтения STATUS.md задай вопрос инструментом `question` (не текстом). Если владелец в первом же сообщении уже поставил задачу или назвал инструмент — меню пропусти и сразу переходи к разделу «Скилл инструмента».

Вопрос 1 — «С чем работаем сегодня?» (header «Работа»), четыре варианта:

- «Скачивание» — группы ВК, картинки из интернета, открытые датасеты, экспорт Telegram.
- «Чистка папки» — дубли, рамки, вотермарки, пережатые JPEG.
- «Отбор и подписи» — отбор по условию, по словам подписи, короткие подписи, сборка в одну папку.
- «Подготовка к обучению» — размер и формат, обучающий набор, кадрирование людей, маски лиц.

Вопрос 2 — инструмент внутри выбранной группы (header «Инструмент»): варианты — инструменты группы из таблицы ниже, label — имя инструмента, description — колонка «что делает». Владелец может вписать свой вариант: это прямое указание.

Затем спроси, с какой папкой работаем (полный путь внутри `<папка датасетов>`), если владелец её ещё не назвал.

## Инструменты

Проект OpenCode — папка `<папка dataset_tools>`, каждый инструмент лежит в своей подпапке. Запуск — всегда с полными путями: `<папка dataset_tools>/venv/Scripts/python.exe <папка dataset_tools>/<папка инструмента>/<скрипт> <аргументы>`; для vk_dataset — `<папка dataset_tools>/venv/Scripts/python.exe <папка dataset_tools>/vk_dataset/vkds.py ...`. Никогда не вызывай `.bat`: при ошибке он ждёт нажатия клавиши.

| Группа | Инструмент | Скрипт | Что делает |
| --- | --- | --- | --- |
| Скачивание | vk_dataset | `vkds.py` | фото групп ВК: альбомы и стена, подписи, журнал вызовов; скиллы `vk-dataset` и `vk-agent-scenarios`, не tool-скилл |
| Скачивание | ddg_images | `ddg_images.py` | картинки по поисковым запросам (Bing, DuckDuckGo, SearXNG) с журналом CSV |
| Скачивание | duck | `duck.py` | поиск в открытых датасетах с подписями (COYO, PixelProse) по словам подписи и фильтрам; CSV, затем скачивание с подписями |
| Скачивание | telegram_dataset | `telegram_dataset.py` | фото из экспорта канала Telegram с чистыми подписями |
| Чистка | deduplicate | `dedup.py` | копии одной картинки → `<папка>_duplicates`; `--gpu`, `--dry-run`, `--undo`, просмотр `--review` |
| Чистка | remove_borders | `remove_borders.py` | рамки, линии, баннеры срезает на месте; оригиналы в `<папка>_backup`; `--dry-run` даёт отчёт и листы; `--undo` |
| Чистка | watermark | `watermark.py` | находит вотермарки и закрашивает их; результат в `<папка>_watermark_removed`; `--dry-run` даёт отчёт и маски |
| Чистка | jpeg_cleanup | `jpeg_cleanup.py` | сильно пережатые JPEG находит и восстанавливает; оригиналы в `<папка>_backup`; `--dry-run`, `--undo` |
| Отбор | judge | `judge.py` | оставляет фото, подходящие под условие словами, остальные → `<папка>_rejected`; команды пишешь ты, запускает владелец (общая модель Ollama); `--dry-run`, `--undo` |
| Отбор | extract_keywords | `extract_keywords.py` | фото, в подписи которых есть слова, → `<папка>_<слово>`; `--undo` |
| Отбор | recaption_json | `recaption.py` | короткая подпись `.short` рядом с `.txt` через локальную модель; долгий прогон на той же модели Ollama — запускает владелец, как judge |
| Отбор | flatten_dataset | `flatten_dataset.py` | фото и подписи из всех подпапок в одну папку под нормальными именами; `--undo` |
| Подготовка | normalize | `normalize.py` | уменьшает до заданной площади и приводит к одному формату, на месте или в копию `-o`; в консоли спрашивает подтверждение — ты зависнешь: сначала `--dry-run`, вопрос владельцу (question), боевой прогон только с `--yes` |
| Подготовка | k2prep | `prep.py` | обучающий набор для AI Toolkit или musubi в `_prep_<папка>`; `--report` — сухой прогон; `--in-place` спрашивает в консоли без флага подтверждения — не использовать |
| Подготовка | reframe | `reframe.py` | кадрирует фото людей на объект съёмки → `<папка>_reframed` |
| Подготовка | face_masks | `make_face_masks.py` | маски лиц в `_controls` рядом с фото; вырезки лиц отдельным скриптом (см. README) |
| Подготовка | rebalance_medium | `rebalance_medium.py` | только для подписей, начинающихся со слов о носителе («A color photograph ...»); по запросу владельца |

Не в меню: `pastvu`, `classify`, `pipeline` — им нужны образцы, база или файлы заданий архитектора. Если владелец их называет, предупреди об этом и дальше действуй по тому же правилу.

Общие правила для любого инструмента: сначала сухой прогон (`--dry-run` или `--report`), разбор его отчёта, вопрос владельцу (question), потом боевой прогон. Инструменты ничего не удаляют: убранные файлы лежат в папке-соседке (`<папка>_duplicates`, `_backup`, `_rejected` и другие), это норма. Подпись `.txt` и другие файлы с тем же именем переезжают вместе с фото. Файлы dataset_tools не править: код, README и `install.bat` — только читать.

## Скилл инструмента

У каждого инструмента есть свой скилл `tool-<имя>`: имя папки инструмента, где `_` заменено на `-` (`remove_borders` → `tool-remove-borders`). Когда инструмент выбран:

1. Посмотри список доступных скиллов. Есть `tool-<имя>` — загрузи его и работай по нему.
2. Нет — построй его сам (ниже), скажи владельцу одной строкой, что скилл создан и где лежит, и продолжай задачу: README уже у тебя в контексте.
3. Скилл есть, но команда из него завершилась ошибкой вида «unrecognized arguments» или флаг пропал из `--help` — инструмент обновился: перестрой скилл заново тем же порядком и скажи об этом владельцу.

### Как построить скилл

Источники — только два, в этом порядке:

1. `<папка dataset_tools>/venv/Scripts/python.exe <папка dataset_tools>/<папка инструмента>/<скрипт> --help` — единственный источник имён флагов. Флаг, которого нет в `--help`, в скилл не попадает.
2. `<папка dataset_tools>/<папка инструмента>/README.md` — назначение, что получается на выходе, ловушки. Читай частями не больше 300 строк за раз; пропускай разделы об установке, устройстве алгоритма и истории версий. Из README в контексте нужны только факты для скилла, не пересказ.

Запиши файл `<папка dataset_tools>\.opencode\skills\tool-<имя>\SKILL.md` по шаблону ниже. По-русски, не длиннее 60 строк, команды — в форме запуска через `<папка dataset_tools>/venv/Scripts/python.exe`. Ничего не выдумывай: нет в `--help` и README — нет в скилле. Больше никаких файлов не создавай и не меняй.

    ---
    name: tool-<имя>
    description: <одна строка: что делает инструмент и когда загружать этот скилл>
    ---

    ## Назначение
    <две строки: что делает, что получается на выходе>

    ## Запуск
    `<папка dataset_tools>/venv/Scripts/python.exe <папка dataset_tools>/<папка инструмента>/<скрипт> <папка> [флаги]`

    ## Типовые команды
    - сухой прогон: <команда с --dry-run или --report>
    - боевой прогон: <команда>
    - откат: <команда с --undo, если есть>
    <ещё 1–2 команды, если инструмент без них не имеет смысла>

    ## Что получится
    <папки-соседки и файлы: куда уходят убранные файлы, где отчёт и листы, где резервная копия>

    ## Перед боевым прогоном
    <что проверить в отчёте сухого прогона; нужна ли видеокарта и сколько примерно длится; вопрос владельцу>

    ## Ловушки
    <из README и --help: что инструмент никогда не делает, вопросы в консоли и флаг для них, ограничения на формат и имена файлов>

    Источник: README и --help инструмента на <дата создания скилла>.

### После создания

Новый скилл может появиться в списке доступных только после перезапуска OpenCode — в этой сессии он тебе и не нужен, README уже прочитан. В STATUS.md добавь строку: какой скилл создан и когда.
