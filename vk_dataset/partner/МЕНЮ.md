# Меню инструментов: как агент работает со всем набором dataset_tools

Этот файл — для владельца. Он описывает, как агент в начале сессии спрашивает, с чем работать, предлагает меню и сам обзаводится инструкцией по выбранному инструменту; как это установить и какие права нужны в `opencode.jsonc`. Заглушки те же, что в `ПЕРЕХОД.md`: `<папка dataset_tools>` — ваша копия dataset_tools, `<папка датасетов>` — корень датасетов.

## Как это устроено

В начале каждой сессии агент читает STATUS.md, загружает скилл `dataset-tools-menu` и задаёт вопрос меню «С чем работаем сегодня?» — четыре группы: скачивание, чистка папки, отбор и подписи, подготовка к обучению. Второй вопрос — инструмент внутри группы. Оба вопроса идут штатным инструментом OpenCode `question`: вы выбираете пункт или вписываете свой ответ. Если вы с первого сообщения ставите задачу («убери дубли в папке ...»), меню не показывается.

У каждого инструмента своя инструкция для агента — скилл `tool-<имя>` в `.opencode\skills\`. Писать их заранее не нужно: при первом выборе инструмента агент сам читает его `--help` и README и записывает скилл: по-русски, не длиннее 60 строк, с командами запуска и ловушками. Это занимает несколько минут на вашей модели. Дальше агент продолжает задачу, а в следующих сессиях сразу загружает готовый скилл и README больше не читает.

Инструменты в меню: vk_dataset, ddg_images, duck, telegram_dataset; deduplicate, remove_borders, watermark, jpeg_cleanup; judge, extract_keywords, recaption_json, flatten_dataset; normalize, k2prep, reframe, face_masks, rebalance_medium. Не в меню — `pastvu`, `classify` и `pipeline`: им нужны наши образцы, база или файлы заданий. Прогоны judge и recaption_json на модели Ollama по-прежнему запускаете вы: агент пишет команды и читает отчёты.

## Установка

Три шага в папке проекта `<папка dataset_tools>\vk_dataset`.

1. Скилл меню: создайте папку `.opencode\skills\dataset-tools-menu\` и положите в неё файл `SKILL.md` с текстом из `partner\skill_dataset-tools-menu.md`.
2. AGENTS.md: внесите правки по списку `partner\AGENTS_меню.md` — короткие строки в §1, §2, §3, §8, §9, §12 и новый раздел 13. Таблица инструментов в AGENTS.md не нужна, она в скилле.
3. Права в `opencode.jsonc` — раздел ниже.

После этого перезапустите OpenCode в папке проекта и пройдите проверку из конца `AGENTS_меню.md`.

## Права в opencode.jsonc

Агенту нужно четыре вещи: показывать меню, читать и запускать инструменты из родительской папки, записывать скиллы `tool-*` в папку проекта и ничего больше в dataset_tools не менять. В вашем `opencode.jsonc` права — упорядоченный список правил, побеждает последнее совпавшее, поэтому порядок важен.

Проверьте и при необходимости добавьте:

- Меню: инструмент `question` по умолчанию разрешён. Если меню не появляется или каждый вопрос требует подтверждения, добавьте правило `{ "action": "question", "effect": "allow" }`.
- Чтение и запуск инструментов: правила `external_directory` и `read` с `allow` на `<папка dataset_tools>/*` уже есть (по ним агент читает README и запускает `--help`). Запуск через `..\venv\Scripts\python.exe` идёт инструментом `bash`, отдельных правил не требует.
- Скиллы инструментов: после запрета `edit` на `<папка dataset_tools>/*` и после разрешений на `STATUS.md` и `tmp/*` добавьте

      { "action": "edit", "resource": "<папка dataset_tools>/vk_dataset/.opencode/skills/tool-*/*", "effect": "allow" }

  Запреты `edit` на `vkds/*`, `tools/*`, `judge/*`, датасеты и оба запрета на чтение токена остаются после него, последними в списке: они важнее.
- Скиллы: инструмент `skill` по умолчанию разрешён; отдельного правила не нужно. Если вы когда-нибудь ограничивали его, разрешите `dataset-tools-menu` и `tool-*`.

Если в вашей версии OpenCode права записаны не списком, а объектом `permission` с ключами по инструментам, те же правила выглядят так (внутри одного ключа тоже побеждает последнее совпавшее):

    "permission": {
      "question": "allow",
      "external_directory": { "<папка dataset_tools>/**": "allow" },
      "read": { "<папка dataset_tools>/**": "allow", "<папка dataset_tools>/vk_dataset/vk_token.txt": "deny" },
      "edit": {
        "<папка dataset_tools>/**": "deny",
        "<папка dataset_tools>/vk_dataset/STATUS.md": "allow",
        "<папка dataset_tools>/vk_dataset/tmp/**": "allow",
        "<папка dataset_tools>/vk_dataset/.opencode/skills/tool-*/**": "allow"
      }
    }

Пути в `opencode.jsonc` пишутся прямыми слэшами.

## Как этим пользоваться

- Начало сессии: ответьте на два вопроса меню или сразу напишите задачу с именем папки. Папку называйте полным путём внутри `<папка датасетов>`.
- Первый выбор инструмента: агент сообщит, что создал скилл `tool-<имя>`, и продолжит. Откройте файл `.opencode\skills\tool-<имя>\SKILL.md` и просмотрите: он по-русски, команды начинаются с `..\venv\Scripts\python.exe`, флаги взяты из `--help`. Если агент сбился на английский, попросите переписать скилл по-русски.
- Скилл попадает в список доступных после перезапуска OpenCode. В той сессии, где он создан, агент работает по прочитанному README, терять ничего не нужно.
- Неудачный скилл: удалите его папку в `.opencode\skills\`, при следующем выборе инструмента агент построит его заново.
- После `git pull` с обновлением инструмента скилл может устареть. Агент сам перестраивает его, когда команда из скилла падает с ошибкой «unrecognized arguments»; можно и просто удалить папку скилла после обновления.
- Перед любым боевым прогоном агент делает сухой прогон и спрашивает вас. Файлы инструменты не удаляют: убранное лежит в папке-соседке (`<папка>_duplicates`, `<папка>_backup`, `<папка>_rejected` и другие), откуда `--undo` возвращает всё обратно.
- normalize и k2prep задают вопрос в консоли; агент знает: normalize запускать с `--yes` после вашего «да», а `--in-place` у k2prep не использовать.

## Что прислать нам

Один раз, когда наберётся три-четыре скилла `tool-*`: архив папки `.opencode\skills\` с ними. Мы сверим их с инструментами и вернём замечания, если агент что-то понял неверно.
